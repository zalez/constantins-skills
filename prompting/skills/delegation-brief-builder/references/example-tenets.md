# Example tenets

Use these as inspiration when helping users define their own tenets. Always tailor to the specific task — don't just copy-paste these. The best tenets emerge from the actual trade-offs the AI will face in the user's specific context.

Remember the quality test: **a good tenet has a meaningful opposite.** Both sides should be legitimate choices that someone could reasonably prefer. If nobody would argue the other side, it's a truism, not a tenet.

## How to use these with users

When suggesting tenets during an interview:

1. **Listen for implied trade-offs.** If the user says "I want it clean and simple," that hints at "Simple over feature-rich." Make it explicit.

2. **Propose 2–3 at a time.** Say something like: "Based on what you've described, here are a few tenets that might help. Do these resonate?"

3. **Use the table format to test.** If a user proposes a tenet, check the "meaningful opposite" column mentally. If you can't think of a legitimate opposite, help them rephrase it into a real trade-off.

4. **Don't over-tenet.** 3–5 tenets is the sweet spot for most tasks. More than that and they start conflicting with each other or become hard to prioritize.

5. **Prioritization matters.** If two tenets could conflict (e.g., "progress over perfection" vs. "get the architecture right"), help the user decide which wins. The order implies priority.
